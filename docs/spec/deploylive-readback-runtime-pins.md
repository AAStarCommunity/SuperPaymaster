# DeployLive readback + masked runtime pins — schema (draft, frozen for SDK PR B)

Three artefacts, implemented in the SP collector follow-up PR (not on 5a150f6a / v5.5.0-rc.8):

| artefact | path | schema string |
|---|---|---|
| readback | `readback.json` in the DeployLive evidence dir and its archive | `deploylive-readback/1` |
| getter policy | `deployments/readback-policy.json` | `readback-policy/1` |
| masked runtime pins | `deployments/runtime-pins.<chainId>.json` (committed, like `creation-pins.<chainId>.json`) | `runtime-pins/1` |

All integers are JSON strings in decimal (no float). All hashes/bytes are lowercase `0x` hex. Addresses are
EIP-55 checksummed. Unknown/not-applicable values are `null`, never omitted and never `"0x"`-as-absence.

---

## 1. `runtime-pins/1` — expected runtime code per release artifact (offline)

Source: the release build (profile.default, solc 0.8.33, viaIR, evm cancun, runs 500; Registry and
TimelockHandoverBootstrap 200 — same artefact selection as `script/rehearsal/deploylive_runtime.release_artifact`,
i.e. `compilationTarget` + runs + evmVersion + viaIR; exactly one DISTINCT (bytecode, deployedBytecode) pair — several artifact files are allowed when they are byte-identical, and any difference between candidates is a failure). Generated by a script in the PR and
recomputed in CI from a clean build (same mechanism as creation pins); the file for each chain is byte-identical
(immutables are masked, so the expectation is chain-independent) and CI `cmp`s them.

SuperPaymasterAdmin is also pinned at runs 500 with `creationPin: "embedded in SuperPaymaster"`, because its creation code is embedded in SuperPaymaster rather than separately creation-pinned.

```jsonc
{
  "schema": "runtime-pins/1",
  "compiler": {"solc": "0.8.33", "viaIR": true, "evmVersion": "cancun"},
  "creationPinsSha256": "0x…",           // sha256 of deployments/creation-pins.<chainId>.json it was built with
  "artifacts": {
    "<ReleaseName>": {                    // the 25 names: DeployLivePins.sol list + TimelockHandoverBootstrap
      "optimizerRuns": "500",
      "runtimeLength": "12345",           // bytes of deployedBytecode.object
      "immutableRanges": [                // from deployedBytecode.immutableReferences, sorted by start
        {"id": "1234", "start": "167", "length": "32", "name": "REGISTRY", "type": "contract IRegistry"}
      ],
      "hasImmutables": true,
      "maskedRuntimeKeccak": "0x…",       // keccak256(runtime with every immutable range zero-filled)
      "rawRuntimeKeccak": "0x…"           // keccak256(deployedBytecode.object as compiled; immutables = 0 placeholders)
    }
  }
}
```

**Masking rule** (identical to `deploylive_runtime.matches`, which the checker already applies to Registry, SP
and TimelockController):
- Mask = zero-fill exactly the byte ranges in the compiler's `deployedBytecode.immutableReferences`
  (`start`, `length`, every reference of every immutable id). Nothing else is masked.
- Why: an immutable's value is written into the runtime by the constructor at deployment (addresses of the
  registry, token, EntryPoint, …), so it differs per deployment/chain; everything else in the runtime, including
  the trailing CBOR metadata (which commits to the source and settings), must match byte for byte.
- On-chain comparison: `len(eth_getCode) == runtimeLength` (else mismatch); zero-fill the same ranges in the
  on-chain code; `keccak` must equal `maskedRuntimeKeccak`. A range outside the code, a non-positive length, or an
  empty code is a mismatch (fail closed).
- Contracts with no immutables: `immutableRanges: []`, `hasImmutables: false`, and
  `maskedRuntimeKeccak == rawRuntimeKeccak` (stated so the equality is expected, not a bug).
- Immutable VALUES are not ignored: `readback/1` records them per range (below), so they can be checked against
  config addresses instead of disappearing under the mask.

## 2. `deploylive-readback/1` — what was actually read on chain (one block)

Written by the post-deploy checker after `checker PASS`, before archive. `checker.PASS.json` gains
`readbackSha256`; archive verifies and copies it (same binding as config/broadcast). All reads are pinned to one
block (`eth_getCode`/`eth_getStorageAt`/`eth_call` use EIP-1898
`{"blockHash": h, "requireCanonical": true}`). The pinned cast 1.7.1 help documents only heights/tags
for its `--block` option, so the checker uses JSON-RPC directly and local ABI encoding/decoding.
It collects each state request once, freezes the snapshot before the assertion traversal, and writes
that same snapshot only if every row passes. Historical log ranges end at the pinned number;
the canonical header at that number is re-read after corroboration and immediately before writing.
A change in any consumed header field fails. A second provider is mandatory on every chain except 31337 in the current attaching drivers. Its endpoint is supplied via `DEPLOYLIVE_SECOND_RPC_FILE`, never printed, with a different
hostname from the primary. Operator-selected endpoints must be independently operated: different
hostnames alone cannot prove organizational independence. Production records both provider names (`endpointProvider` and `secondProvider.name`) and rejects equal names after trimming and case folding, in addition to the different-hostname rule. The second provider checks the same chain,
header number, hash and timestamp and replays EVERY recorded state request, including assertion calls, getters, Safe reads,
balances, all storage slots, code and logs. No sampling is permitted. `eth_call`, `eth_getStorageAt`,
`eth_getBalance` and `eth_getCode` use the snapshot's EIP-1898
`{blockHash, requireCanonical:true}` selector on both providers. Comparison is type-aware, determined by RPC method and field name, never inferred from the value.
DATA (code, ABI return data, storage words, log data/topics, every hash and address) is lowercased
with length preserved and compared byte for byte. QUANTITY (balance, block number, log index,
transaction index) ignores leading zeros. Object field order is ignored; list order and all fields
remain significant. `allEqual` means equality under these rules, not raw JSON text equality. Any difference fails with method, target and selector/slot, never a URL.

`eth_getLogs` has no EIP-1898 form. Both providers replay the IDENTICAL address/topics and
fromBlock..toBlock query, with toBlock equal to the snapshot number. Both must report the
snapshot hash at that number before and after log replay. Every returned log's blockHash must
match BOTH providers' canonical hash at its blockNumber; each distinct log block number is
read once per provider and cached. Both normalized log lists must agree item by item in order.
The primary replay must also equal the recorded snapshot. A canonical mismatch fails naming
the block. Log mismatch labels include normalized fromBlock/toBlock and a SHA-256 digest of
case-normalized topics, distinguishing queries on the same address without exposing endpoints.
`secondProvider.requests` counts all replayed state requests, including logs.
Chain-31337 output sets `secondProvider: null`, `singleProvider: true`, and `singleProviderNote` set to the note
`single provider: not evidence of on-chain state` (also emitted in the checker log). Production
records `singleProviderNote: null`. This evidence is not a proof against colluding providers.

Field sources:
- `contracts[]`: every address-valued key of `config.<env>.json` that names a deployed contract (registry,
  registryImpl, superPaymaster, spImpl, spAdminImpl, staking, gToken, sbt, aPNTs, pnts, xPNTsFactory,
  xPNTsFactoryV2, xPNTsTokenV1Impl, xPNTsTokenV2Impl, xPNTsTokenV2Ext, blsAggregator, dvtValidator,
  reputationSystem, aoaProtocolRegistry, policyRegistry, globalTierSource, superPaymasterLens,
  paymasterFactory, paymasterV4Impl, microPaymentChannel, x402Facilitator, timelockController,
  handoverBootstrap; only policy-authorized zero-address keys are listed with `address` zero and all reads `null`). The
  configKey→artifact mapping is a committed table in the PR (`deployments/readback-artifacts.json`), not inferred.
- `erc1967` is read for EVERY contract (not only known proxies); a non-proxy shows zero addresses. The SDK should
  treat "is a proxy" as "implementation != 0", and check implementation == the matching `*Impl` config key.
- `version`: present for contracts whose ABI has `version()` (on main: AOAProtocolRegistry, APNTsCapped,
  BLSAggregator, DVTValidator, GToken, GTokenAuthorization, GTokenStaking, GlobalTierSource, MicroPaymentChannel,
  MySBT, Paymaster, PaymasterFactory, PolicyRegistry, Registry, ReputationSystem, SuperPaymaster,
  SuperPaymasterLens, X402Facilitator, xPNTsFactory, xPNTsFactoryV2, xPNTsToken, xPNTsTokenV2). For a proxy, the
  call goes through the proxy. Expected strings come from `deployments/release-versions.rc8.json`, which the same
  PR extends to every contract above.
- `addressGetters`: enumerated from the ABI of the contract's release artifact (for a proxy: the ABI of the
  implementation artifact, called through the proxy), not from a hand list, so every address getter of every
  pinned contract is present. Tuple outputs are recorded as JSON objects keyed by component name (positional
  index if unnamed); only address-carrying components are kept. Each ADDRESS LEAF in `resolvesTo`
  is a sorted array of ALL matching labels: `config:<key>`, `external:<key>`, and `zero`.
  Thus address-array outputs have arrays of label arrays. An unaccounted address leaf resolves to `[]`
  and fails. A legitimately empty array (`value: []`, `resolvesTo: []`) passes only with the getter's
  explicit `emptyAllowed: true` and `why`. Non-empty arrays check each element independently.
  `policyMatches` is always true in written evidence. Getter reverts normally fail; a documented
  `unreadableAllowed` exception has `value: null`, `resolvesTo: null`, `policyMatches: true` and its
  name in `unreadable`. The committed policy currently allows no unreadable getter.
- `wiring`: getter names are the ABI names on main (abis/SuperPaymaster.json, abis/Registry.json); values as
  returned. Pending-state getters (pendingOwner, pendingAPNTsToken, pendingBLSAgg) are also recorded as
  `SP.pendingOwner` etc. so a non-zero pending value is visible.

SDK use: take addresses and read values from `readback.json`, re-read the same fields independently on two RPCs
at the same block, and compare; compare `maskedRuntimeKeccak` offline against `runtime-pins/1`.

Versioning: any field rename/removal bumps the schema string (`/2`); adding a field keeps `/1`.


## 3. `readback-policy/1` — committed getter expectations

```jsonc
{
  "schema": "readback-policy/1",
  "rule": "resolved ∩ allowed ≠ ∅; resolved = [] fails; array outputs: each element independently",
  "getters": {
    "Artifact": {
      "getter": {"allowed": ["config:semanticKey"], "why": "Source and intended wiring"},
      "optionalArray": {"allowed": ["config:token"], "why": "Empty before issuance", "emptyAllowed": true},
      "pendingAddress": {"allowed": ["zero"], "why": "No pending change",
                         "zeroAllowed": "Explicit allowed-zero getter and source reason"}
    }
  },
  "immutableBindings": {
    "SuperPaymaster": {
      "EXTENSION": {"allowed": ["config:spAdminImpl"], "why": "Constructor-created admin delegate target"}
    } // every pinned artifact, with {} only for artifacts without immutables
  },
  "unreadableAllowed": {"Artifact": {"getter": "Source-backed reason for expected revert"}},
  "zeroAllowedConfigKeys": {"pnts": "DeployLive skips production Mycelium issuance"}
}
```

`allowed: []` with `emptyAllowed: true` describes getters that must return empty arrays; no
nonempty address leaf can satisfy that entry. The production factory token lists and inert Paymaster
supported-token lists use this shape. Other `allowed` lists contain only the semantic expected label(s), normally one; two nonzero sources require
both to be explained in `why` (e.g. template owner versus initialized proxy owner). Wildcards and
unknown labels fail. `zeroAllowed` is an optional nonempty reason string declaring a getter itself
allowed-zero. Otherwise `zero` requires an allowed config key in `zeroAllowedConfigKeys`. Zero-valued
allowed labels must also have this permission; an alias cannot silently authorize zero.
`emptyAllowed` is an optional boolean, only valid for array-bearing getters and always accompanied by
`why`. It applies at array nodes, never to unaccounted address leaves. Policy and ABI coverage are
checked in both directions, including inherited getters, proxy implementation ABIs and Admin; stale
or missing getter entries fail, as do stale unreadable exceptions. Artifacts with no address getters
have an explicit empty object.

The intersection rule relies on each allowed key's own value being right: contract-address keys are
checked against runtime pins (and H1 rejects unauthorized zero addresses); governance, guardian and
operator keys are bound by DeployLive's input manifest and Safe checks. External values come from
the committed external-deps file. The native ETH sentinel is a constant in that file, not executable
contract code. Duplicate labels are retained rather than collapsed, and any matching allowed label
is sufficient; an unrelated duplicate label neither grants nor revokes permission.

Shared proxy/implementation ABIs include documented template zero defaults. The checker separately
rejects zero proxy getters whose policy names a nonzero required config address, so a template's
zero permission cannot excuse missing proxy wiring. `maskedMatchesPin` must be true for nonzero
mapped artifacts. Optional exact clones instead require the EIP-1167 template and configured target;
zero optional records retain their existing null read fields. Both proxy ERC-1967 implementation
slots must equal `registryImpl` / `spImpl` respectively.

`deployments/readback-noncontracts.json` lists every scalar and array principal/external/absent-clone address
key and its reason. Address-valued config keys must equal artifact-map keys plus that explicit list;
unknown or missing keys fail. `expectedGovernor` is a declared local-only output, never accepted on
production chains. Address arrays (guardians and ledgers) also require exact classification coverage and retain their independent checks. Empty arrays are included; the three numeric amount arrays are explicitly excluded.

The checker count is `238 + 2 * guardianN`: this includes config completeness, snapshot policy,
second-provider evidence, block-hash recheck, two factory codehash rows, GToken cap and channel self-address.
The rq3op gate still requires exact equality, not a range or a count learned from the checker output.

**The full rule** is the `rule` string together with `emptyAllowed` and `zeroAllowedConfigKeys` (and a getter-level
`zeroAllowed`): the `rule` string alone does not state the empty-array or zero permissions. A policy entry covers
exactly one address leaf; a getter whose output is a tuple or carries more than one address leaf is refused
("policy unsupported") until per-field policy exists, which would be `readback-policy/2`. `emptyAllowed` is valid
only on a getter whose output carries an array; on any other getter the policy entry itself fails.

## 4. Round 4 additive immutable bindings and execution context

Every immutable range includes compiler `VariableDeclaration.name` and
`typeDescriptions.typeString`. Generation selects the full matching compilation from
`out/build-info/*.json`, including imported AST declarations; per-artifact ASTs are insufficient.
The matching deployed bytecode identifies the compilation. Missing or ambiguous declarations fail.
`foundry.toml` remains byte-for-byte equal to origin/main. Only isolated pin-generation builds enable
`FOUNDRY_BUILD_INFO=true` with `FOUNDRY_OUT=out-clean`. Artifact checks use committed name/type metadata
without requiring ASTs; default clean checks rederive and compare it.

`immutableBindings` covers EVERY immutable name in every pinned artifact regardless of type.
Missing and stale entries fail. Each entry has exactly one of three kinds:
- Address: `allowed` labels plus `why`, using the resolved/allowed intersection rule.
- Exact value/hash: `expectedUint`, `codehashOf`, or `chainId: true`, plus `why`.
- Known gap: exactly `{"unbound": "<reason>"}`.

Every reference must be a 32-byte word; repeated references must agree. Address rules require
zero high twelve bytes. Every unbound word is checked by shape: zero high twelve bytes and
nonzero low twenty bytes FAIL with `unbound immutable has address shape: <Artifact>.<name>`.
There is no known-address heuristic and no dependence on committed types for this decision.
Every `_cachedChainId` must use `chainId: true` and equal the observed chain ID exactly.
The record repeats these checks. No AST is needed at PASS time. The independent CI clean-build
check is `python3 script/rehearsal/runtime_pins.py deployments/runtime-pins.10.json --check`:
it re-derives names/types from full build-info and compares, without modifying foundry.toml.

The four helper links (SP EXTENSION, both factory implementations, V2 token EXTENSION) are all
immutables. Their target config keys must also be nonzero under the existing config coverage rule.
Successful production `pnts` is zero: its row says `zero address; not deployed`. The existing exact
EIP-1167 check only applies if present; a successful production run does not perform a clone comparison.

The row formula is `238 + 2 * guardianN`; with two guardians the expected total is 242.
Address checks remain in snapshot policy; factory codehashes, GToken cap and channel self-address also have dedicated rows.

The checker requires an explicit `DEPLOYLIVE_EVIDENCE_DIR` (or explicit local-test
`DEPLOYLIVE_LOCAL_EVIDENCE`). Invalid arguments, config integers or provider names must not remove
prior evidence. `DEPLOYLIVE_ENDPOINT_PROVIDER` must be a provider name, never a URL, and is validated
at input loading and checker startup. rq3 operators must set it and `DEPLOYLIVE_EVIDENCE_DIR`;
`pinned_tools` forwards both into its restricted child environment.


## Round 6 bindings

`GTokenAuthorization._cap` has an `expectedUint` decimal-string rule: `21000000000000000000000000`.
The authority is `contracts/script/v3/DeployLive.s.sol:175`, not config `expectedCap` (the APNTs cap).
Every 32-byte occurrence must equal this value. Readback records `{value, expectedUint, policyMatches}`,
and record validation repeats the equality. `MicroPaymentChannel._cachedThis` is uint256 in the AST,
but `contracts/lib/solady/src/utils/EIP712.sol:54` assigns `uint256(uint160(address(this)))`.
It therefore uses the address rule: low twenty bytes equal `config:microPaymentChannel`, high twelve
bytes zero, with every occurrence agreeing. Missing bindings for either field fail coverage.

The `__self` rules are exactly `SuperPaymaster -> config:spImpl`, `Registry -> config:registryImpl`,
and `SuperPaymasterAdmin -> config:spAdminImpl`. Proxy addresses are invalid constructor self-addresses.

## Known gaps: unbound non-address immutables

Inventory below is the distinct `(artifact, name)` set in all three committed runtime-pin files after
subtracting bound fields: 18 remaining entries. They are derived at construction by the pinned creation
code from constructor name/version constants, chainId and the contract's own address. The own address is
bound through `_cachedThis` (and UUPS `__self` where present); the checker verifies the RPC chain ID.
Those checks constrain the inputs but do **not** prove these masked cache bytes equal the derived values.
Their guarantee is the creation-code pin and plan comparison on the DEPLOYMENT path; the checker alone cannot prove them. The missing step is independent recomputation and comparison of every runtime occurrence. chainId is now bound exactly.

Sources: OpenZeppelin `singleton-paymaster/lib/openzeppelin-contracts-v5.0.2/contracts/utils/cryptography/EIP712.sol:67`
(constructor), `:80` (cache validity); Solady `contracts/lib/solady/src/utils/EIP712.sol:53` (constructor).
Domain inputs: GToken `contracts/src/tokens/GTokenAuthorization.sol:114` (`GToken`, `1`);
xPNTs template `contracts/src/tokens/xPNTsToken.sol:303` (empty name, Permit version `1`);
channel `contracts/src/paymasters/superpaymaster/v3/MicroPaymentChannel.sol:160` (`MicroPaymentChannel`, `1.0.0`).
APNTs uses `AAStar PNTs` from `contracts/script/v3/DeployLive.s.sol:215`, through
`contracts/src/tokens/APNTsCapped.sol:71`, and Permit version `1`.

universally harmless: cachedChainId mismatch can just force correct recomputation, and ShortString

## Round 8 provider and evidence boundary

The committed approved-provider list is `deployments/readback-providers.json`, with hostname suffixes per
entry. Names are trimmed and case-folded. Both endpoints must match different approved entries.
The parsed, lower-case hostname must end with a committed dot-prefixed suffix; userinfo is
refused. Thus `eth-sepolia.g.alchemy.com` matches `.alchemy.com`, but `evilalchemy.com` does not.
Endpoints are never printed; identity diagnostics contain only the provider name and pass/fail.
The suffix inventory covers known RPC host families: Alchemy `*.g.alchemy.com`, Tenderly
`*.rpc.tenderly.co`, PublicNode `*.publicnode.com`, Infura `*.infura.io`, and QuickNode
`*.quiknode.pro` / `*.quicknode.com`. No DNS or network validation is performed.
Residual trust: the committed suffix list is correct and the two organisations are independent.
CNAME/alias resolution to one service is NOT checked; that would require trusted resolution.
Log completeness cannot be proven from returned data: logs silently omitted by both providers
are undetectable. The completeness check is agreement of two independent providers.
Single-provider permission is limited to chain 31337, or loopback Anvil launched by this driver
run with its own live PID, port and launch-argument attestation. Current drivers attach to existing
nodes and have no such attestation: they grant ONLY the chain-31337 exception. Every other chain,
including production-chain loopback forks, requires two providers. A non-loopback production
endpoint always requires the second provider, with no override. REHEARSAL and node metadata
cannot grant an exception.

The evidence directory resolves below the approved worktree `cache/` root. The root itself,
paths outside it, symlink components and a symlink readback.json are refused before unlinking.

## Serialized config containers

Only eight flat arrays are allowed: `guardians` (committee principals),
`gTokenMintRecipients` and `gTokenMintAmounts` (allocation ledger), `stakeAccounts` and
`stakeAmounts` (staking ledger), `stakeRoles` (bytes32 staking role identifiers), `ticketTreasuries` and `ticketAmounts` (ticket ledger).
The sole allowed dictionary is `artifactCompileSettings`: exactly the release artifact names, each with the reviewed `evmVersion`, `viaIR`, and `optimizerRuns` values. This records build provenance. No other dictionary values, arrays of containers, or other array keys are allowed. Address arrays
still require exact inventory coverage and valid address elements; amounts use the integer parser.


### Corroborated header evidence

The complete block header is fetched from both providers at every block whose fields are used.
The exhaustive consumed-field list is `number` (snapshot/range identity), `hash` (EIP-1898 and
log canonicality), and `timestamp` (record evidence). Neither the checker nor readback consumes
`baseFeePerGas` or other header fields. All three fields are compared with their RPC types;
returned numbers must also match the requested heights. Snapshot headers are bracketed before
and after replay; historical log headers are cross-checked and cached per height. The record's
block object is populated from the cross-checked snapshot header. Any recorded
`eth_getBlockByNumber` response is also checked against both providers at its concrete height;
it is no longer exempt metadata that can inject unchecked evidence. The final primary recheck
must match all three cross-checked fields. Chain 31337 retains its explicitly non-evidentiary
single-provider mode.

### Production artifact fixture exclusion

Both the runtime checker and runtime-pins CLI use the same production directory validator.
The directory must resolve strictly to an existing directory. Every symlink component is refused,
and path components are compared case-insensitively: `contracts/test/**` and any `fixtures`
component are forbidden. Test-only explicit artifact-helper injection is separate from production
selection. Path checks cannot recognize fixtures copied into an innocuously named directory:
artifact provenance for that case rests on the deploy-day build stamp (clean HEAD plus
`foundry.toml` hash). No additional copied-artifact detector is claimed.
