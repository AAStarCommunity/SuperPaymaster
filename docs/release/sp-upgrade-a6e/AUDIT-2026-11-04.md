Independent adversarial audit of the pre-sampling manifest executor on `origin/main`
(`7f0a0f4b9eb8`) against [MANIFEST-DESIGN.md](MANIFEST-DESIGN.md) and
[script/upgrade/README.md](../../../script/upgrade/README.md) (§ "Pre-sampling manifest").

Scope: `script/upgrade/manifest_exec.py`, the `sp_upgrade_exec.py` and `script/a3a/a3a_exec.py`
helpers it calls, and `script/upgrade/release_evidence.py`. Everything here is offline: no RPC endpoint,
no chain, no key, no fork. **No production code was changed**; the diff adds only this report,
`script/upgrade/audit/test_audit_findings.py`, the probe harness
`script/upgrade/audit/probe_gate_removal.py`, and the probe logs under
[`audit-2026-11-04/`](audit-2026-11-04/).

What this audit does **not** establish: fork/bytecode compatibility (error selectors, Ownable variants,
anvil snapshot semantics), cryptographic PoP validity, or anything about Phase C (not implemented in this
slice; see N3/S6). Those still require the authenticated Amsterdam fork rehearsal on the real pin.

## Summary

- Phase A/B/D construction is faithful to the design: every transaction row, its order, calldata
  shape, nonce sequence, Safe nonce order (5a, 5b, B2a, 6c, 6d), the B2/B4 rules and the Phase D
  topology match MANIFEST-DESIGN.md. `validate_plan` rebuilds the whole plan from the pin and inputs,
  so a tampered packet cannot diverge silently. No Critical or High defect was found.
- **One design contradiction (F-01, Medium):** DSR's 2026-11-02 ruling makes D the only sampled
  operator and keeps N paused, but the executor accepts any subset of the pause list and the
  shipped fixture/test (`test_unsampled_operator_remains_paused`) asserts that **Anni is unpaused**.
- Three missing preconditions/report fields (F-02..F-04, Low).
- **F-05 (Medium, test gap):** many section-6 STOP gates — the pre-send sender/pending/Safe nonce checks,
  Safe-state, SP-owner and pending-token checks, post-send nonce checks, B4 nonce consumption, the
  dual-endpoint pin checks — can be deleted without any test failing.
- **Gate-removal probes:** 182 `a.need` statements in the Phase A/B/D code were removed one at a time.
  125 survive (the whole `test_manifest_exec.py` stays green), 35 of them because the suite
  never executes the statement at all. The biggest uncovered areas are the B4 three-way controls
  (`b4_controls`, patched out in every test), the unbacked-swap control, the B2a mint trace, the A17
  drain check, ETA read-backs, the manifest `pre_send` fresh-estimate/block-gas checks, and the
  post-run `pin_recheck`. By code reading these gates fail closed; they were not exercised on a fork in this audit, and unit
  tests do not defend them against regression.

### F-01 (Medium) — sampled operator set contradicts the DSR 2026-11-02 ruling

- **Design:** MD §3 Phase C, "Resolved by DSR 2026-11-02": "**D is the only sampled operator.** B3
  unpauses D only; N stays paused, receives no V2 token and no funding." The README (§ Mandatory
  external-input JSON) still describes `sampled` as any "nonempty sorted unique list of
  configured/inventoried operator addresses", i.e. the README predates the ruling.
- **Code:** `validate_external` checks only order/uniqueness/non-emptiness (`manifest_exec.py:626-629`);
  `build_plan` checks `sampled ⊆ pauseList` (`:1327`) and appends one `setOperatorPaused(op,false)` per
  entry to the activation batch (`:1483`). The shared fixture `input_data()` samples `[D, Anni]`
  (`test_manifest_exec.py:124`), and `test_unsampled_operator_remains_paused` asserts `ANNI: 0`
  (unpaused) after 6d.
- **Scenario:** inputs carrying the README's example form `[D, N]` (or the fixture's own value) build,
  validate, calibrate and hash cleanly. 6d unpauses N. N is drained, so it cannot sponsor immediately,
  but `deposit`/`onTransferReceived` ignore the pause (MD §3 Timing), so any later APNTsCapped transfer to
  N's operator account makes a second, unreviewed operator live during the G3 window, and the G3
  matrix's "which operators are sampled" record no longer matches the chain. The packet hash the author
  approves would encode it.
- **Fix condition:** reject `sampled != [deployer]` (gate `sampled_deployer_only`), update `input_data()`
  and `test_unsampled_operator_remains_paused`, and the README. The audit test then passes and loses its marker.

### F-02 (Low) — budget shortfall is not reported

- **Design:** MD §4 "If it is short, **STOP and report the exact shortfall**; never reduce n"; §6 the
  same.
- **Code:** `budget()` raises `budget_<label>` with `observed=False, expected=True`
  (`manifest_exec.py:1875`). The failure record written by `main()` therefore carries no amount; the
  operator has to recompute it by hand.
- **Scenario:** D's pin balance is 1 wei short of the A/B/D cost: rehearsal stops with
  `STOP: budget_deployer` and `failure.json` says `observed: false`.
- **Fix condition:** put `{required, balance, shortfallWei}` into the gate record's `observed`.

### F-03 (Low) — token-swap ETA not bound to the reviewed literal

- **Design:** MD §2 "`pendingAPNTsTokenEta == 1794226596` = 2026-11-09 12:16:36 UTC, from S7 block
  12048088"; §4 repeats it as the 6d floor.
- **Code:** `sp_upgrade_exec.collect` reads the value (`:349`) and `validate_pin` only type-checks it
  (`:725`); `build_plan` derives `activationScheduleNotBefore = pendingAPNTsTokenEta − 48h` (`:1356`) from
  whatever the pin holds. The capped token address *is* bound to a literal nonce (`:769`), the ETA is not.
- **Scenario:** if S7 were re-sent or `setAPNTsToken` re-queued before the pin (D still owns SP), the ETA
  shifts later; the manifest silently re-derives a later 6c floor instead of stopping on a changed
  precondition, and §9's decision card date would be wrong. Live rehearsal still reads the true value, so
  the swap itself cannot run early — hence Low.
- **Fix condition:** reject the pin unless `pendingAPNTsTokenEta == 1794226596` (gate
  `pin_pending_token_eta`; fixtures switch to the literal).

### F-04 (Low) — old aggregator `slashPolicyAdmin` not read back

- **Design:** MD §3 Phase D table, old BLSAggregator: "Ownable, owner D; `slashPolicyAdmin` also D
  (read back)".
- **Code:** `collect` checks `old_aggregator_owner` (`manifest_exec.py:1163`) but never calls
  `slashPolicyAdmin()` on the old aggregator; the first read is `handover_gate`'s post-admin check
  (`:1594`), after D has already sent `D.old_aggregator.admin`.
- **Scenario:** if the old aggregator's policy admin were a third party at the pin, that party could change
  slash thresholds/bps on the retired-but-callable contract until Phase D, and the pin (and §9 card) would
  not show it. Phase D still overwrites it, so the end state is correct.
- **Fix condition:** read it at the pin and require D (gate `old_aggregator_slash_policy_admin`).

### F-05 (Medium, test gap) — section-6 STOP gates that no test defends

- **Design:** MD §6 makes these hard stops: "a sender nonce differs from the plan", "a read-back differs",
  "an estimate exceeds the planned gas limit", plus the §2 owner/pointer preconditions. The release
  `mutation` evidence (`MUTATIONS`, `manifest_exec.py:37`) proves only four manifest gates are load-bearing.
- **Evidence (actual probe runs, section 3):** with the statement deleted, all 235 tests stay green for:
  `pre_send` `sender_nonce` (`:1936`), `pending_nonce` (`:1937`), `safe_nonce` (`:1938`), `safe_state`
  (`:1939`), `old_activity_unchanged` (`:1943`), `dvt_activity_unchanged` (`:1945`), `SP_owner` (`:1949`),
  `pending_token`/`pending_token_eta` (`:1955-1956`), `onchain_safe_hash` (`:1970`), `fresh_estimate`/`block_gas_limit`
  (`:1976-1977`); `run_manifest` `post_nonce`/`post_safe_nonce` (`:2151-2152`), `manifest_receipt_gas` (`:2146`),
  `steps_complete`/`controls_complete` (`:2198-2199`), `post_swap_*` (`:2203-2206`); `execute_b4`
  `B4_nonce_consumed`/`B4_safe_nonce` (`:1758-1759`); every `b4_controls` assertion (`:1784-1818`); `collect`
  `old_aggregator_owner`, `pointer_owner`, `old_pointer`, `anni_eoa`, `stake_not_unlocking`; `main`
  `independent_pin`, `simulation_pin`, `pin_recheck`.
- **Scenario:** a later refactor drops or weakens `pre_send`'s nonce comparison (e.g. compares `pending`
  against the wrong field). CI stays green and the mutation evidence still says PASS. A foreign
  transaction from D/A/E between the pin and a step would then be caught later, if at all, by the receipt
  identity check, not by the gate MD §6 names, and the run's STOP record would point at the wrong cause.
  By code reading the gates are correct today and fail closed (not exercised on a fork in this audit); what is
  missing is regression protection.
- **Why no expectedFailure test:** the code is not defective. The fix is test-side: one negative test per
  gate asserting `record['gate']`. After that the probe for each listed line must report `killed`;
  `probe_gate_removal.py --site LINE --failfast` is the acceptance check.

### Not raised as defects (reviewed)

- **SP "stripped" creation hash equals the full hash** (`creation_hashes`, `:293`; `evidence_full_creation_*`,
  `:264`). Correct for this tree: `foundry.toml` sets `bytecode_hash = "none"`, so SP metadata has no
  path-dependent IPFS hash and any difference is executable. Only the verifier needs CBOR stripping.
- **`early_bls` / `funded_swap` revert reason is the shared `InvalidConfiguration()`.** The cause is
  pinned by state: B1's read-back proves `pendingBLSAgg == A7` before `early_bls`; `funded_swap` waits
  for the token ETA first. `early_swap` proves its cause by maturing the same call.
- **`factory_binding` adapts its expected error** to whether `xpntsFactory()` is zero
  (`:2086`). With a stale non-zero V1 factory it proves "token not issued by the wired factory",
  not "before `setXPNTsFactory`" — still a rejection. See open question Q4.
- **Committee selector check** searches hex substrings (`:1589-1592`); a false match can only STOP.

## 3. Gate-removal probes

Method ([`probe_gate_removal.py`](../../../script/upgrade/audit/probe_gate_removal.py)): every
`a.need(...)` **statement** inside the 31 Phase A/B/D functions (`build_plan`, B2/B4/handover gates,
`pre_send`, controls, `run_manifest`, `solvency_probe`, `collect`, `main`, …; release-evidence, fraud-fixture,
Safe-governance and A3a-history parsers excluded) is replaced by `pass` in the AST **in memory**; the
module is installed as `manifest_exec` and the unchanged `test_manifest_exec.py` runs in a fresh process.
`killed` = at least one test fails; `survived` = all 235 tests pass. Killed probes ran with
`--failfast` (first failing test recorded); survivors ran the full suite. A separate coverage run
(gates kept, statements recorded) says whether the suite reaches each statement at all
([`coverage.json`](audit-2026-11-04/probes/coverage.json)).

Performance note: the harness memoises the read-only `ast.parse`/`ast.walk` used by conformance-evidence
validation (the module's only such call site, asserted); gate decisions are unchanged and the suite drops
from ~235 s to ~66 s. The baseline under the harness is green with the same 235 tests.

Reading the list:
- *never reached*: the statement is not executed by any test. Most sit in functions that the rehearsal
  tests patch out (`b4_controls`, `mint_trace`, `unbacked_swap_control`) or branches no test enters
  (`batch_readback(activated=False)`, A17's drain check, the `eta` predicate kind, `pre_send(measured=True)`,
  `main()`'s post-fork re-checks).
- *reached but unasserted*: the statement executes, but either no test feeds it a failing value or a
  later gate rejects the same input first (defence in depth). These are the cheapest to fix: one negative
  test asserting that exact gate name each.
  A survivor is not automatically a weakness: for example `6d_token_eta` (L1687) is logically implied by
  `6c_schedule_floor` + `6d_timelock_eta`, because the floor is derived as `pendingAPNTsTokenEta - 48h`. Many
  tests use a bare `assertRaises(a.Gate)` without checking `record['gate']`, so the first gate that fires hides
  the others. The safety-relevant survivors are collected in F-05.
