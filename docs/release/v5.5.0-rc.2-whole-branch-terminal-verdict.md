## 3. Adversarial results

### Timelock history and possible bypasses

`contracts/script/v3/TimelockRoleHistory.sol:24-86` requires an explicit deployment block, rejects zero/future values, and requires code at B and no code at B−1. A late starting block cannot hide an earlier grant under an honest historical RPC. `_blockQuantity` (`:89-99`) encodes canonical hex quantities, including `0x0` for the preceding block when B=1. RPC/code-history/log errors propagate; there is no catch-to-success, guessed-block fallback, or opt-out flag.

The scanner covers the inclusive range B through the script's fork head in consecutive, non-overlapping batches of at most 10,000 blocks (`:37-68`). Every returned log must be non-removed, from the selected timelock, and within its batch; ordering is strictly increasing by block and block-global log index (`:46-56`). Non-overlapping batch ranges also establish cross-batch order. Constructor-block grants must establish the four expected role/account pairs (bitmask 15, `:64,70,104-112`); an empty history cannot pass. Providers with lower range limits cause failure, rather than partial acceptance. This is a fixed batch size, not an adaptive pagination algorithm.

Replay (`:116-149`) tracks each distinct `(role, account)` through grants and revocations. Unknown roles are rejected even if subsequently revoked. Malformed role-topic counts revert. For every seen pair, including revoked pairs, a successful 32-byte live `hasRole` response must agree with replay. Active admin must be the timelock itself; active proposer/canceller/executor must be the governance Safe, and exactly four pairs must remain active. Consequently an unlisted admin/proposer/executor, open executor, missing required member, omitted revocation of a seen pair, or stale replay/live disagreement cannot pass. Revoked extra members are correctly allowed.

`contracts/script/v3/DeployAPNTsCapped.s.sol:317-342` adds exact default-OZ runtime matching and retains the 48-hour delay and known-address checks before requiring the complete replay predicate. Both external-timelock deployment (`:129-130`) and final `verify` (`:156-172`) use it. The fresh local-chain branch (`:120-127`) instead checks the genuine logs of the timelock it has just deployed itself from the default artifact; this is not a bypass for a caller-supplied timelock. The fixed OZ runtime has no public arbitrary role-admin rewrite, so role-administration drift is not silently admitted.

**Accepted trust boundary, inherited from #485 F2:** runtime matching does not bind creation code. A malicious custom constructor could silently initialize an extra holder, emit the expected four grants, and return the standard runtime. Only pairs seen in logs are live-cross-checked. Such an externally supplied timelock can defeat the event-set proof. The supported procedure therefore requires deployment by the runbook using the default creation artifact; this assumption is explicit at `TimelockRoleHistory.sol:10-13` and `DeployAPNTsCapped.s.sol:322-324`. To support arbitrary third-party timelocks, bind the creation transaction/input and constructor arguments, rather than treating this predicate as an unconditional proof. Likewise, a dishonest/truncating RPC can omit an entire unseen holder; one RPC is trusted here, and this is not independent two-provider attestation. No new bypass within the stated deployment/provider assumptions was found.

The regression suite `contracts/test/scripts/DeployAPNTsCapped.t.sol` includes genuine local-EVM grant/revoke logs (`:99-162`) and a scanner harness that substitutes RPC I/O only (`:22-78`). Tests at `:170,178,185,193,205,214` separately cover three chunks, extra admin, unordered logs, missing constructor grant, late start and live mismatch. Unknown-role rejection (`:124`) uses a **revoked** unknown role so another final-set guard cannot mask its removal; changed-runtime rejection (`:138`) appends unreachable code while preserving getters and roles. These tests do not constitute a fresh real archive-RPC scan.
