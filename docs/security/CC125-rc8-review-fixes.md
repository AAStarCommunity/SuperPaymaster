# rc.8 defensive-review fixes

SuperPaymaster 5.5.4 and SuperPaymasterLens 1.2.5 address Low #2, #4 and #5 of the AI-assisted defensive review of tag v5.5.0-rc.8 (5a150f6a). The review's Medium (an unconfirmed guardian slash queue cannot be renewed after its 7-day freeze) is kept as designed: renewal would let a single guardian key freeze operator withdrawals indefinitely, which the expiry exists to prevent. Low #3 (a COMMUNITY can sponsor any active role for another address) is the sponsored-onboarding path DeployLive uses for the genesis operator and is documented rather than changed.

- **#2, same-bundle minTxInterval bypass.** For a nonzero minTxInterval, validation keeps an EIP-1153 transient admission marker scoped to (operator, sender). A second admission of the same pair in one transaction is rejected with the existing signature-failure result. The marker is written only after the token reservation succeeds; operators with a zero interval never read or write it. The persistent postOp timestamp and the validAfter computation are unchanged.
- **#4, stale sponsorship eligibility after a failed exit sync.** Permissionless `reconcileSBTStatus(address)` on the Admin extension clears a true `sbtHolders` entry only if `Registry.getUserRoles(user)` is empty, and otherwise reverts with `InvalidConfiguration`. It never grants eligibility and emits `SBTStatusUpdated(user, false)`. The core fallback routes the selector to the extension; `SuperPaymasterAdminCalls` and the merged proxy ABI expose it. Registry.sol is unchanged (17 B of EIP-170 headroom): every role exit goes through `exitRole`, which removes the role from `userRoles` before the non-fatal SP sync, so an empty `getUserRoles` means no registered role remains.
- **#5, Lens false success after token SP rotation.** `dryRunValidation` reads the token's `SUPERPAYMASTER_ADDRESS()` through the existing safe static-call helper before `previewLock`. A failed probe or a different paymaster returns the existing `DRYRUN_LOCK_REJECTED`, so SDK reason-code mapping is unchanged.

Tests: `test_RC8_A_*`, `test_RC8_B_*` and `test_RC8_C_*` each fail with the corresponding source change reverted. The EntryPoint opcode-trace harness (`test_OP011_*`) now counts paymaster TLOAD/TSTORE: one extra read and write on the nonzero-interval path, none for a zero interval. Rate-limit tests that model two transactions run with `forge-config: default.isolate = true`, because time warps inside one Foundry test do not clear transient storage.

For repo:sdk and repo:dvt: consume the regenerated SuperPaymaster (core, Admin, merged) and Lens bundles together. `reconcileSBTStatus` is additive; `version()` strings advance as above; dry-run result codes and the persistent storage layout are unchanged. Creation pins for chains 10 and 31337 and the DeployLive test fixture are refreshed for the new core and Lens bytecode. The OP Sepolia (11155420) and Sepolia pins, deployed addresses and online configuration are unchanged; rc.8 stays the deployed and paper-pinned release.
